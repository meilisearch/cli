# Contributing

This page takes you from a clone of the repository to a pull request. The conventions are in [`CLAUDE.md`](CLAUDE.md). The promises made to users are in [`docs/contract/`](docs/contract/). When this page and the contract disagree, the contract wins.

## Set up

You need Node 22 or newer, pnpm 11 (`corepack enable` installs it), and Docker for the integration tests.

```sh
pnpm install
pnpm openapi   # the OpenAPI documents the tests read, into openapi/ (never committed)
```

The management document is in a private repository, so `pnpm openapi` needs `gh auth login` to fetch it. Without it, you still get the Meilisearch API document. The Meilisearch API commands need only this document.

## Run it

```sh
pnpm build                              # after every change
./bin/run.js --help

./bin/run.js config set --project local --project-url http://localhost:7700 --project-api-key masterKey
./bin/run.js get health --project local          # JSON: indented in a terminal, compact when piped
./bin/run.js get indexes --project local --debug # HTTP trace on stderr, keys masked
```

The management commands use the session of `meili auth login`, on production. To test against another Cloud (the development one or a local one), point the CLI to it with environment variables. These variables have no flag and are not in the README:

```sh
export MEILI_MANAGEMENT_URL=https://api.meilisearch.dev
export MEILI_MANAGEMENT_TOKEN=...                        # a personal access token of that Cloud, created by an administrator
./bin/run.js get projects

# or log in to that Cloud, in a new shell: both URLs, and the OAuth application registered there
export MEILI_MANAGEMENT_URL=https://api.meilisearch.dev
export MEILI_MANAGEMENT_DASHBOARD_URL=...                # the dashboard of that Cloud, which hosts the consent page
export MEILI_MANAGEMENT_CLIENT_ID=...                    # the uid of a public OAuth application registered there
./bin/run.js auth login
```

`MEILI_MANAGEMENT_TOKEN` takes priority over the session. Unset it to use the session of `auth login`. `pnpm openapi:management` needs a GitHub token that can read `meilisearch/meilisearch-cloud`. `pnpm gen:management` regenerates the client from the document.

`pnpm link --global` adds a `meili` command to your PATH. This command runs your checkout.

## Test

```sh
docker compose up -d   # Meilisearch on :7700 with the master key masterKey
pnpm test              # build, manifest, then unit, contract and integration tests
pnpm lint              # pnpm lint:fix applies the safe fixes
pnpm typecheck
```

- **Unit tests** mock HTTP with msw and snapshot the `--help` and the JSON output of each command.
- **Contract tests** keep the code and `docs/contract/` in sync. If one of them fails after a code-only change, the doc needs the change too.
- **Integration tests** run the built binary against `localhost:7700`. When nothing answers there, they are skipped with a notice. They are required in CI.

`pnpm test -u` updates the snapshots. Use it only for an interface change that you made on purpose. To run one suite only: `pnpm exec vitest run --project unit`. Details are in [`docs/contract/testing.md`](docs/contract/testing.md).

## Add a command

Run `/add-command get stats` with Claude Code, or follow "How to add a command" in `CLAUDE.md`. In short: one command per pull request. The command name comes from its API routes, by the rules of [`docs/contract/commands.md`](docs/contract/commands.md). The pull request includes a snapshot test, an integration test, the manifest regenerated by `pnpm gen:manifest`, and a changeset.

## Release

Every pull request that changes what the published package does adds a changeset. A changeset is a small file in `.changeset/` with the version bump and one line for the changelog. A change to the docs of this repository, to the tests or to the CI needs no changeset, because a user of the package would not notice it. Help texts and error messages are code, and users see them, so a change to them needs a changeset.

```md
---
"@meilisearch/cli": minor
---

Add `meili get stats --index <index>`.
```

The line names the command with its required flags. The optional flags are in `--help`. Use `patch` for a fix, `minor` for a new command or flag, and `major` for a breaking change of the contract. Before 1.0, a breaking change also uses `minor`.

The release runs in `.github/workflows/release.yml`, on `main`, after the tests. While changesets are waiting, `changesets/action` opens or updates a "Version Packages" pull request. It bumps the version, writes `CHANGELOG.md` from the changesets and regenerates `oclif.manifest.json`. Merging this pull request publishes the version:

1. on npm, as `@meilisearch/cli`, with a `v<version>` tag and a GitHub release;
2. as archives with Node inside, built by `pnpm archives` in `dist/` and attached to the GitHub release, for `scripts/install.sh`;
3. on Homebrew, in the `meilisearch/homebrew-tap` repository, from the formula `.github/homebrew/meili.rb`.

See ADR 0017 for the channels and the reasons.
